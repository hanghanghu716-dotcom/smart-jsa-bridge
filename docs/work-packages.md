# 작업별 서류 묶음과 도면

## 2026-10-08 재시도 보완

도면·출력 PDF 업로드 후 메타데이터 저장에 실패하면 같은 파일 ID로 재시도합니다. Storage가 중복 파일을 반환할 때 이미 저장된 파일을 다운로드해 크기와 SHA-256을 대조한 뒤에만 연결합니다. 파일 내용이 다르면 원본을 덮어쓰거나 잘못된 스냅샷을 저장하지 않고 실패로 처리합니다. `ResourceAlreadyExists` 코드와 기존 409/중복 메시지를 지원합니다.

서비스 테스트로 업로드 후 메타데이터 실패, 응답 유실, 반복 재시도의 단일 레코드 유지, 같은 경로의 다른 파일 거부, 권한/서버 오류 시 메타데이터 미생성을 검증했습니다. Community 실제 계정의 저장 한도 검증 결과는 `free-storage-quota.md`에 기록했습니다. 기존 원본·출력본 삭제 정책은 변경하지 않았습니다.

실제 테스트 계정의 기존 `QA_20261008_PAPER_…` 비공개 출력본으로도 현재 서비스를 두 번 재호출했습니다. 실제 Storage 중복 응답을 처리해 동일 출력본 ID를 반환했고, 원본 PDF 해시·전체 메타데이터·스냅샷이 모두 유지됐습니다. 새 파일은 만들지 않았습니다.

## 이용 방법

내 라이브러리의 **작업별 서류 묶음** 또는 `/:lng/work-packages`에서 시작합니다.

1. **새 묶음**을 만들고 이름과 버전 이름(`ver.1`, `야간작업용` 등)을 입력합니다.
2. 내 JSA를 불러오고 PTW·TBM·점검표·사용자 양식을 추가합니다. 문서를 제외하거나 순서를 바꿀 수 있습니다. JSA 내용·상세 레이아웃은 기존 편집기를 사용하고, 저장한 JSA/레이아웃을 묶음으로 불러옵니다.
3. 양식에 입력란·표를 추가하고 제목, 항목명, 열, 행을 편집합니다. **표준값 재사용**, **작업할 때 입력**, **수기 작성용 공란** 중 하나를 지정합니다. 실측값·측정시각·측정자·현장 확인·날짜·작업자는 표준값으로 저장할 수 없습니다. 개인 양식으로 저장한 뒤 다른 묶음에서 불러올 수 있습니다.
4. 도면 보관함에 PDF·PNG·JPG를 업로드합니다. 도면번호와 개정번호를 입력하고, 묶음에 도면을 추가한 후 필요한 페이지를 선택합니다. 여러 도면을 연결할 수 있습니다.
5. 도면 위에 자유선·직선·화살표·사각형·타원·구역·텍스트·번호를 표시합니다. 선택 도구로 이동하고 도형 손잡이로 크기를 조절합니다. 글자·번호 크기는 별도 입력란에서 조절합니다. 페이지별 실행 취소/다시 실행을 제공하며 페이지 전환 시 취소 기록은 초기화됩니다. 표시 자체는 모든 페이지에 보존됩니다.
6. 묶음을 **저장**합니다. 새 버전은 이름/버전 이름을 바꾸고 **독립 복제본으로 저장**합니다. 도면 원본은 공유하고 각 묶음의 표시와 문서 내용은 독립적으로 복제합니다.
7. **새 작업 시작**에서 공통 정보와 이번 작업의 값을 입력합니다. 날짜·담당자·작업자·측정값·확인값은 새로 입력합니다. 필요하면 이번 작업에서만 도면 표시를 바꿉니다.
8. 출력할 문서를 선택하고 **PDF 저장·보관** 또는 **인쇄·보관**을 누릅니다. 비공개 보관에 성공한 뒤 다운로드/인쇄가 진행됩니다. 동일한 입력으로 재출력하면 같은 보관본을 사용하고, 입력을 수정하여 출력하면 별도 보관본을 만듭니다.
9. **출력본 보관함 → 열기**에서 당시 공통 정보와 원래 PDF를 확인합니다. PDF와 전체 입력 기록(JSON)을 내려받을 수 있습니다.

새 개정 도면은 새 원본으로 업로드합니다. 묶음에서 원본을 교체하면 표시 위치 확인이 필요하며, 확인 전 출력은 막힙니다. 과거 원본과 출력본은 덮어쓰지 않습니다.

## 경계와 제한

- 공개 JSA, Case Study, 공개 PDF 저장 경로와 분리되어 있습니다. JSA 공개·재사용 허용은 이 묶음이나 도면을 공개하지 않습니다.
- 기존 JSA 저장 제한은 기존대로 적용됩니다. 묶음은 별도 자료이며 공개 JSA의 조회수·활용수 집계에 포함하지 않습니다.
- 파일당 도면 20MB, PDF 200페이지, 묶음당 문서 40개, 양식 표당 8열/100행, 출력 PDF 100페이지/40MB를 상한으로 둡니다. 이미지 원본은 5천만 픽셀까지 허용하고 출력용 도면은 긴 변 2,200픽셀 이내로 렌더링합니다.
- 출력은 기존 JSA와 같은 HTML 캡처 방식이며 A4 세로/가로를 문서별로 적용합니다. CAD 축척 출력이나 벡터 보존을 보장하는 기능이 아닙니다. DWG 편집, 도면 마커와 위험요인의 자동 연결·범례는 후속 확장 대상입니다.
- 묶음 편집과 이번 작업 입력을 같은 브라우저의 계정별 초안으로 임시 저장합니다. 7일이 지난 초안은 다음 접근 시 정리하며, 초안당 5MB까지 지원합니다. 원본이 바뀌면 자동 복원하지 않고 다른 탭이 변경한 초안을 덮어쓰지 않습니다. 브라우저 데이터 삭제·저장 차단·용량 초과 시 복구할 수 없으므로 저장 오류 안내를 확인해야 합니다. 재사용 묶음 저장과 출력본 보관은 별도입니다.
- 복원은 같은 미완성 작업을 이어 쓰는 기능입니다. 다른 날 작업에는 초안을 지우고 시작하며 날짜·측정값·현장 확인을 다시 입력합니다. 복원 시 지역 요건 검토 확인은 해제합니다. 공용 PC에서는 작업 후 초안을 정리해야 하며, 브라우저 초안은 암호화 보관함이 아닙니다.
- 화면과 복구·사용량·PDF 안내는 10개 지원 언어를 제공합니다. 국가별 양식의 요구사항과 전문 용어 검수 상태는 `regional-document-packs.md`에서 별도로 관리합니다.
- 보관 PDF/원본을 지우거나 덮어쓰는 일반 사용자 기능은 제공하지 않습니다. 개인정보 삭제 요청·계정 삭제 시 원본 파일 정리는 운영자 절차가 필요합니다.
- 추가 유료 서비스를 연결하지 않습니다. 저장 용량은 기존 Supabase 프로젝트의 사용량에 포함됩니다.

## 저장 구조와 배포

`20261002131450_private_work_packages.sql`이 기존 마이그레이션 뒤에 필요합니다. 현재 연결된 프로젝트에는 적용했습니다. `20261004123346_work_storage_summary.sql`도 2026-10-04 적용했습니다. 새 테이블 없이 본인 파일의 사용량만 조회하는 함수를 추가합니다. 익명 호출은 거부하고 다른 사용자 ID를 입력받지 않습니다.

| 저장소 | 내용 |
| --- | --- |
| `work_packages` | 사용자 이름·버전 이름·재사용 문서/표/도면 표시 |
| `work_form_templates` | 다른 묶음에서 불러올 개인 양식 |
| `work_drawings` | 변경 불가능한 원본 경로·개정번호·페이지 수·SHA-256 |
| `work_outputs` | 변경 불가능한 출력 PDF 경로·SHA-256·전체 작업 입력/문서/표시 스냅샷 |
| `work-bundle-assets` | 비공개 원본과 출력 PDF 파일 |

4개 테이블 모두 RLS를 사용합니다. 로그인한 소유자만 접근할 수 있고 익명 권한은 없습니다. 서버 트리거는 다른 소유자의 도면·묶음 참조, 잘못된 파일 경로·페이지 번호, 실제 파일 없이 메타데이터만 등록하는 요청을 거부합니다. Storage에 별도의 제한 정책을 두어 향후 넓은 정책이 추가되어도 사용자 간 파일 접근과 원본/출력본의 갱신·삭제를 차단합니다. 관리자 키는 브라우저에 필요하지 않습니다.

파일 업로드와 메타데이터 등록은 하나의 트랜잭션이 아닙니다. 같은 화면에서 재시도하면 같은 파일 ID를 사용합니다. 업로드 성공 뒤 메타데이터 등록이 실패하고 화면을 종료하면 비공개 고아 파일이 남을 수 있으므로 운영자가 보관 정책에 따라 정리해야 합니다. 출력 보관 실패는 인쇄/다운로드 성공으로 표시하지 않습니다.

- `npx vite --config scripts/work-package-fixture/vite.config.js` 후 `http://127.0.0.1:5175/scripts/work-package-fixture/index.html`: 계정·서버 저장 없이 실제 편집기/출력기를 확인하는 개발 전용 화면. 테스트 전용 저장 서비스로만 연결하며 배포 빌드에 포함하지 않습니다.

- 2026-10-04 실제 테스트 계정 2개로 로그인, 묶음·양식·도면·출력본 저장, 재로그인 후 입력값/스냅샷/PDF 복원을 확인했습니다. 다른 계정·익명 조회, 다른 계정 수정, 소유자 위조, 타인 도면 연결, 원본 덮어쓰기 요청은 차단됐습니다. 일반 사용자 인증으로 확인했으며 관리자 권한으로 대체하지 않았습니다.
- 실제 계정의 브라우저에서 묶음 수정·저장, 작업 입력, PDF 생성·비공개 보관도 성공했습니다. 로컬 최신 화면에서는 미저장 묶음 수정 → 다시 열기 → 이어쓰기 → 저장 → 다시 열기 순서로 값 복원과 초안 정리를 확인했습니다. 검증 자료는 `QA_20261004_PRIVATE_WORK` 이름으로 비공개 보관합니다.
- 격리 브라우저에서 작업 입력 복원/새 작업 초기화, IndexedDB 동시 쓰기 충돌과 오래된 탭의 삭제 방지, 계정별 초안 분리를 확인했습니다. 실제 프린터, 모든 국가 양식의 실제 계정 출력, Community 한도 도달 시나리오는 이번 실제 계정 검증 범위에 포함하지 않았습니다.

## 파일 사용량과 미등록 업로드 관리

화면은 본인 도면·출력본의 파일 수와 MB, 미등록 업로드 수를 보여 줍니다. Community 비공개 JSA 3개 제한과 별개이며, 새로운 총용량 요금제나 유료 서비스는 도입하지 않습니다.

운영자는 `scripts/work-storage-audit.sql`로 읽기 전용 목록을 확인합니다. 등록된 원본/출력본, 7일 이내 업로드, 형식이 알려지지 않은 경로는 유지합니다. `unregistered_review`는 검토 대상이지 삭제 승인이 아닙니다. 업로드 후 메타데이터 등록이 늦게 재시도될 수 있으므로 업로드 세션 종료와 소유자 확인, 삭제 직전 재등록 여부 확인이 필요합니다. 확실하지 않으면 유지합니다. 삭제가 승인된 파일만 [Storage API](https://supabase.com/docs/guides/storage/management/delete-objects)로 정리하며 Storage 메타데이터를 SQL로 삭제하지 않습니다. 자동 삭제 작업은 설정하지 않았습니다.

2026-10-04 점검에서는 미등록 업로드가 없어 실제 파일 삭제를 실행하지 않았습니다. 계정 삭제/권리 요청에 따른 등록된 원본 삭제는 별도 운영 절차입니다.

## 배포 후 자동 검사

배포 워크플로 마지막에 `scripts/verify-live-release.js`를 실행합니다. 빌드한 manifest와 운영 manifest가 일치해야 하며 18개 지역 × 6개 가이드의 초기 HTML, PDF 형식·해시, Explore 초기 데이터 및 작업 공간 진입 URL을 확인합니다. 실패하면 배포 작업이 실패로 표시되지만 이미 배포한 사이트를 자동으로 되돌리지는 않습니다. 브라우저 편집·로그인·실제 인쇄 검증을 대체하지 않습니다.

가이드와 출력본 보관 화면에는 PDF 새 창 열기 링크를 제공하여 내장 PDF 미리보기가 비어 있는 브라우저에서도 파일을 열 수 있습니다.
