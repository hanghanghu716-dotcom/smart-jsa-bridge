# 작업별 서류 묶음과 도면

## 이용 방법

내 라이브러리의 **작업별 서류 묶음** 또는 `/:lng/work-packages`에서 시작합니다.

1. **새 묶음**을 만들고 이름과 버전 이름(`ver.1`, `야간작업용` 등)을 입력합니다.
2. 내 JSA를 불러오고 PTW·TBM·점검표·사용자 양식을 추가합니다. 문서를 제외하거나 순서를 바꿀 수 있습니다. JSA 내용·상세 레이아웃은 기존 편집기를 사용하고, 저장한 JSA/레이아웃을 묶음으로 불러옵니다.
3. 양식에 입력란·표를 추가하고 제목, 항목명, 열, 행을 편집합니다. **표준값 재사용**, **작업할 때 입력**, **수기 작성용 공란** 중 하나를 지정합니다. 실측값·측정시각·측정자·현장 확인·날짜·작업자는 표준값으로 저장할 수 없습니다. 개인 양식으로 저장한 뒤 다른 묶음에서 불러올 수 있습니다.
4. 도면 보관함에 PDF·PNG·JPG를 업로드합니다. 도면번호와 개정번호를 입력하고, 묶음에 도면을 추가한 후 필요한 페이지를 선택합니다. 여러 도면을 연결할 수 있습니다.
5. 도면 위에 자유선·직선·화살표·사각형·타원·구역·텍스트·번호를 표시합니다. 선택 도구로 이동하고 도형 손잡이로 크기를 조절합니다. 글자·번호 크기는 별도 입력란에서 조절합니다. 페이지별 실행 취소/다시 실행을 제공하며 페이지 전환 시 취소 기록은 초기화됩니다. 표시 자체는 모든 페이지에 보존됩니다.
6. 묶음을 **저장**합니다. 새 버전은 이름/버전 이름을 바꾸고 **독립 복제본으로 저장**합니다. 도면 원본은 공유하고 각 묶음의 표시와 문서 내용은 독립적으로 복제합니다.
7. **새 작업 시작**에서 공통 정보와 이번 작업의 값을 입력합니다. 날짜·담당자·작업자·측정값·확인값은 새로 입력합니다. 필요하면 이번 작업에서만 도면 표시를 바꿉니다.
8. 출력할 문서를 선택하고 **PDF 저장·보관** 또는 **인쇄·보관**을 누릅니다. 비공개 보관에 성공한 뒤 다운로드/인쇄가 진행됩니다. 동일한 입력으로 재출력하면 같은 보관본을 사용하고, 입력을 수정하여 출력하면 별도 보관본을 만듭니다.
9. **출력본 보관함 → 열기**에서 당시 공통 정보와 원래 PDF를 확인합니다. PDF와 전체 입력 기록(JSON)을 내려받을 수 있습니다.

새 개정 도면은 새 원본으로 업로드합니다. 묶음에서 원본을 교체하면 표시 위치 확인이 필요하며, 확인 전 출력은 막힙니다. 과거 원본과 출력본은 덮어쓰지 않습니다.

## 경계와 제한

- 공개 JSA, Case Study, 공개 PDF 저장 경로와 분리되어 있습니다. JSA 공개·재사용 허용은 이 묶음이나 도면을 공개하지 않습니다.
- 기존 JSA 저장 제한은 기존대로 적용됩니다. 묶음은 별도 자료이며 공개 JSA의 조회수·활용수 집계에 포함하지 않습니다.
- 파일당 도면 20MB, PDF 200페이지, 묶음당 문서 40개, 양식 표당 8열/100행, 출력 PDF 100페이지/40MB를 상한으로 둡니다. 이미지 원본은 5천만 픽셀까지 허용하고 출력용 도면은 긴 변 2,200픽셀 이내로 렌더링합니다.
- 출력은 기존 JSA와 같은 HTML 캡처 방식이며 A4 세로/가로를 문서별로 적용합니다. CAD 축척 출력이나 벡터 보존을 보장하는 기능이 아닙니다. DWG 편집, 도면 마커와 위험요인의 자동 연결·범례는 후속 확장 대상입니다.
- 새 작업 화면의 입력은 출력 보관 전까지 현재 화면에만 있습니다. 출력 전 탭을 닫으면 미완성 작업은 복구되지 않습니다. 재사용 묶음 저장과 출력본 보관은 별도입니다.
- 새 화면은 한국어·영어를 제공하고 다른 언어 경로는 영어로 표시합니다. 기존 JSA 문서는 기존 다국어 렌더러를 그대로 사용합니다.
- 보관 PDF/원본을 지우거나 덮어쓰는 일반 사용자 기능은 제공하지 않습니다. 개인정보 삭제 요청·계정 삭제 시 원본 파일 정리는 운영자 절차가 필요합니다.
- 추가 유료 서비스를 연결하지 않습니다. 저장 용량은 기존 Supabase 프로젝트의 사용량에 포함됩니다.

## 저장 구조와 배포

`20261002131450_private_work_packages.sql`이 기존 마이그레이션 뒤에 필요합니다. 현재 연결된 프로젝트에는 적용했습니다.

| 저장소 | 내용 |
| --- | --- |
| `work_packages` | 사용자 이름·버전 이름·재사용 문서/표/도면 표시 |
| `work_form_templates` | 다른 묶음에서 불러올 개인 양식 |
| `work_drawings` | 변경 불가능한 원본 경로·개정번호·페이지 수·SHA-256 |
| `work_outputs` | 변경 불가능한 출력 PDF 경로·SHA-256·전체 작업 입력/문서/표시 스냅샷 |
| `work-bundle-assets` | 비공개 원본과 출력 PDF 파일 |

4개 테이블 모두 RLS를 사용합니다. 로그인한 소유자만 접근할 수 있고 익명 권한은 없습니다. 서버 트리거는 다른 소유자의 도면·묶음 참조, 잘못된 파일 경로·페이지 번호, 실제 파일 없이 메타데이터만 등록하는 요청을 거부합니다. Storage에 별도의 제한 정책을 두어 향후 넓은 정책이 추가되어도 사용자 간 파일 접근과 원본/출력본의 갱신·삭제를 차단합니다. 관리자 키는 브라우저에 필요하지 않습니다.

파일 업로드와 메타데이터 등록은 하나의 트랜잭션이 아닙니다. 같은 화면에서 재시도하면 같은 파일 ID를 사용합니다. 업로드 성공 뒤 메타데이터 등록이 실패하고 화면을 종료하면 비공개 고아 파일이 남을 수 있으므로 운영자가 보관 정책에 따라 정리해야 합니다. 출력 보관 실패는 인쇄/다운로드 성공으로 표시하지 않습니다.

## 검증

- `npm run test:all`: 기존 기능 및 묶음 복제/입력 초기화/도면 교체/좌표 변환 테스트.
- `PGLITE_MODULE=<설치된 @electric-sql/pglite 경로> node scripts/work-packages-db.cjs`: 실제 운영 데이터를 쓰지 않는 격리 PostgreSQL 검사. 다른 계정/익명 접근, 소유자 위조, 외부 도면 참조, 페이지 범위, 원본·보관본 변경 방지, 저장된 과거 입력 보존을 확인합니다.
- `npx vite --config scripts/work-package-fixture/vite.config.js` 후 `http://127.0.0.1:5175/scripts/work-package-fixture/index.html`: 계정·서버 저장 없이 실제 편집기/출력기를 확인하는 개발 전용 화면. 테스트 전용 저장 서비스로만 연결하며 배포 빌드에 포함하지 않습니다.
- 브라우저에서 혼합 방향 6페이지 PDF(위험성평가, PTW, TBM, 점검표, 2페이지 도면)를 생성하고 Poppler로 전 페이지를 렌더링하여 확인했습니다. 주석 이동/문자 크기/취소/다시 실행 및 모바일 가로 넘침도 확인했습니다.
- 로그인한 실제 사용자 계정으로 업로드→저장→다시 로그인→보관함 확인까지의 수동 검증과 실제 프린터 출력은 배포 검수에서 추가로 진행해야 합니다. 자동 검사나 개발 전용 화면을 이 검증의 대체로 간주하지 않습니다.
