## Operating bounds and lifecycle

- Reuse the existing once-daily `government-jobs-daily` schedule. No per-visitor collection or new paid services/API keys.
- Eight prepared adapters; maximum seven sources claimed per invocation. With Work24 disabled and USAJOBS Singapore enabled, seven active sources normally make at most **18** requests/run: USAJOBS US 2, USAJOBS Singapore 1, Korea 5, Queensland 1, Castilla y León 1, Russia 2, Japan 1 list + at most 5 notice pages. Russia may retry each query once for a transient failure, raising the absolute bound to **20** requests/run. Each response is capped at 2 MiB. Russia has an 18-second attempt budget including response body, other calls remain at 12 seconds. The Japanese notices run concurrently and are read only for minimal metadata/deadlines; no recursive links, PDFs, images or full-text storage.
- Seven claims maximum, locked atomically, 20-hour source cooldown. Independent sources run concurrently; each failure preserves other sources and existing records. Invocation timeout 100 seconds, below the Edge free-plan 150-second wall limit.
- Maximum 200 minimal records/source/import. Database upsert preserves operator withdrawal. No paid bulk downloads or AI translation.
- API access is free; hosting still depends on total project usage. These limits do not promise unlimited free hosting.
- Date-only Spanish deadlines keep their original date label and expire after that date in Europe/Madrid, including DST. The original notice governs any earlier exact time. Future application-start dates are not shown early.
- Russian API has no verified closing date; source rechecks and 48-hour stale handling apply. Missing items in a bounded result are not immediately declared closed. Actual withdrawal/earlier closure can precede the next source check; users must verify the original.
- Do not turn the metadata link directory into JobPosting schema, applicant processing or a full-text mirror.

- Russia's 5 November scheduled run stored `source_error`. The former collector discarded the reason; the invocation log shows HTTP 200 for the overall batch, not successful Russian collection. A later live check returned valid data for both queries, taking 9.93 and 9.88 seconds against the former 12-second timeout. This supports latency as a risk, **not proof of the historical failure cause**.
- Russian queries remain sequential: 18 seconds per attempt, one retry for network/timeouts or HTTP 408/429/500/502/503/504. Backoff is one second unless the provider specifies `Retry-After`; a wait over two seconds is not retried during that invocation. Maximum four requests / 76 seconds, leaving time for two 10-second RPC calls within the existing 100-second dispatch. HTTP 401/403/404, invalid JSON/schema and oversize responses are not retried. A failed second query cannot commit a partial sample. Existing stored records and withdrawal decisions retain the same rules.
- Logs now contain only fixed reason codes, source ID and retry attempt. No raw errors, source URLs, headers, API keys or copied job descriptions. `scripts/job-source-recovery.test.js` checks these bounds and failure cases.
- Australia was **already enabled**. The live Queensland list still returns three matching occupational-safety posts. Its footer continues to identify the [Queensland copyright terms](https://www.qld.gov.au/legal/copyright), covering eligible state material under CC BY 4.0 with attribution and exclusions. - At this initial recheck, Singapore was **not connected** (see the subsequently authorized USAJOBS alternative below). Cards identify USAJOBS, link to the original and public-data terms, and disclaim OPM endorsement. Dates use the original USAJOBS Eastern-time convention, explicitly labelled ET, not Singapore midnight.

No new table or column. Seed disabled; deploy the scope/attribution UI before activating and performing the first live import. Zero matching current jobs is a valid outcome and must be reported as zero, not as failed connection or populated with unrelated work.
